# Start here: use your own GitHub account

This is the public starter, not a candidate workspace. **No founder-assigned repository is
needed.** Create your own private copy and send its link back after doing the work there.

## 1. Create your copy

Open [the public starter](https://github.com/chumi-technologies/senior-backend-challenge), click
**Use this template → Create a new repository**, choose **your own GitHub account** as owner,
and select **Private**. Keep the default branch only. A public fork would expose your solution;
you do not need a fork or a founder invitation to start.

## 2. Clone and work

Clone your new repository, not the public starter:

```sh
git clone https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
cd YOUR-REPOSITORY
```

GitHub has initialized its history. **Do not run `git init`, delete `.git`, or reset history.**
Read AGENTS.md before using AI, then README.md and challenge/SESSION.md. A separate branch or
PR is optional. Commit the initial candidate decision checkpoint before implementation; keep
later corrections rather than rewriting an always-right history.

## 3. Send the initial handoff, then update

Commit/push, invite the reviewer account named by the sender in **Settings → Collaborators**,
and send the repository link, SHA, checkpoint SHA, elapsed work and unfinished items.
The sender then supplies a private evidence update. Use the remaining effort budget to revise
and verify, preserve the initial handoff commit, and send the new SHA. See docs/SUBMISSION.md.

Questions go to the original sender by email or message. No special thread, Git reinitialization,
pre-assigned repository or synchronous stage-release call is required. Keep the solution private.
